# MImo V2.5 Pro 因子审查流程

## 概述
新因子或因子逻辑重大修改必须经过独立 AI（MImo V2.5 Pro）**设计审查**通过后才能集成进主策略（SOP §3.0；设计审查 ≠ 统计检验，见下）。

## 审查流程
```
1. 编写《因子设计方案》 → factor_docs/{因子名}_v{n}.md
   内容：定义 / 依据 / 数据处理 / 风险自查 / 待审查问题清单
2. 用 delegate_task 委派给 MImo V2.5 Pro 独立审查
3. 设计审查通过 → 集成进 multi_factor_value.py（SOP §3.0 代码合并前置条件）
4. 审查不通过 → 修改方案 → 重新提交
```

## 审查内容
- 因子的经济逻辑是否成立
- 数据处理是否合理（PIT/TTM/缺失处理）
- 是否与现有因子高度共线
- 是否有已知的学术文献支持
- 风险点和失效场景

## 审查 ≠ 检验（M1 口径统一，2026-08-22）

> 复盘 M1（docs/review_2026-08/M1_审查偷换为有效.md）：本页的"审查"是**设计审查**（防口径错、逻辑漏洞、未来函数），**不防无效因子**。一个设计完美的因子可以完全没有预测力。设计审查通过 ≠ 统计有效。

- **设计审查语境**："设计已审（MImo v2，2026-08-20）"
- **统计检验语境**："有效性未验（v3 检验未执行）"，或"已检验：test_XXX_20260822.md 结论 XX"
- **禁止**："审批通过 / 已批准 / 已通过"单独作为因子可用性依据。
- 因子可用性唯一依据 = factor_registry 状态列 + 检验回填；本页仅记录设计审批。
- 10 个在册因子统计有效性补检为复盘 S1 任务（[[project-review-2026-08]]，最高优先）。

## 为什么需要独立审查
- 用户明确要求：因子深层分析必须经不同 AI 验证后才可使用
- 防止单一 AI 的偏见影响因子选择
- 审查记录可追溯，便于复盘
