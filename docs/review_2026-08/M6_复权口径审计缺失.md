# M6 — 复权口径审计缺失：双口径铁律只管回测引擎，选股层无口径表

> 来源：项目复盘 2026-08-22 第 M6 项（Wiki 全文：G:\quant-investing\wiki\comparisons\project-review-2026-08.md）

## 1. 问题现状

项目定稿了"双口径铁律"（hfq 收益层 / raw 估值执行层），但该纪律只写在回测工程规范里，**选股层各字段各自什么口径没有任何审计表**。项目自己的数据验证实测结论明确：价格水平/市值/成交额类因子必须用不复权价，收益/比率类可 hfq/qfq（rank 不变）——选股层恰恰混用了两类字段且无记录。

## 2. 证据

- 选股层字段口径现状（无任何文档声明）：
  | 字段 | 来源 | 口径 |
  |------|------|------|
  | 60日涨跌幅 (MOM_60D) | 东财 spot | 疑似 qfq，未验证 |
  | 市盈率-动态 (EP) | 东财 spot | 现价/年化当期EPS，未验证 |
  | 市净率 (BP) | 东财 spot | 现价/最新净资产，raw 性质 |
  | 总市值 (LOG_MCAP) | 东财 spot | raw，未声明 |
  | 换手率 (TURNOVER) | 东财 spot | 当日口径，未声明 |
  | 量比 (VOL_RATIO) | 东财 spot | 盘中快照，未声明 |
- `docs/SOP.md`、`docs/factor_docs/`、wiki 中均无"选股层字段口径审计表"
- 双口径铁律出处：`backtest_engineering_spec_v2.1.md` §2.1——适用范围只写了回测引擎，选股层未提及

## 3. 为什么是错

口径未审计 = 口径风险不可见：某天接口改字段口径（qfq 改 raw 或反之），因子静默漂移，没人会发现。而项目已实测过的教训（市值/价格水平类用错复权口径 Spearman 直接崩到 0.37）在选股层完全没有防线。

## 4. 修改要求

1. 新建 `docs/factor_docs/data_caliber_audit.md`（口径审计表），字段：
   | 字段名 | 用途（因子） | 来源接口 | 原始定义 | 复权口径 | 报告期口径 | 验证日期 | 验证方法 | 验证结论 | 风险 |
   对选股层 + 引擎输入层全部字段（上表 6 项 + yjbb/zcfz 财务字段 + 引擎的 raw/hfq 价格/市值/ST/停牌字段）逐行登记
2. "待验证"项（60日涨跌幅、销售毛利率、市盈率-动态）按 C9 子项③④实测后回填；**未验证的字段在"风险"列标红"未验证，禁止作为最终结论依据"**
3. SOP §3.2 因子研究 SOP 增加第 0 步："字段口径登记——新因子接入前先在 data_caliber_audit.md 登记口径，未登记不得入 WEIGHTS"
4. 双口径铁律的适用范围在 v2.1 规范中补一句："本铁律同样适用于选股层因子构建（见 data_caliber_audit.md）"
