## 1. 问题现状

选股层（multi_factor_value.py）的因子构建存在 6 处口径/逻辑问题，直接影响打分质量。逐项如下。

---

### 子项 1：EP 用"市盈率-动态"——横截面口径随披露进度漂移

- **证据**：`code/multi_factor_value.py` L137/139/140（`市盈率-动态` 过滤）、L273（`df['EP'] = 1.0 / df['市盈率-动态']`）；registry L23 备注自写"1/动态PE"
- **为什么是错**：动态PE = 现价 ÷ 年化当期EPS（Q1×4、Q3×4/3）。同一横截面上：已发 Q3 的公司用 9 个月数据年化，只发 Q1 的公司用 3 个月数据年化——季节性强、披露进度不同的公司**不可比**；与 BP（最新净资产口径）不同步。价值因子的主源口径错误。
- **修改要求**：EP 改用 **TTM 口径**：`EP = EPS_TTM / raw最新价`（EPS_TTM 已在 `build_quality_factors` 产出，逐股 PIT 正确）；或 `EP = 归母净利TTM / raw总市值`（总市值口径规避每股复权歧义，符合双口径铁律）。fallback：若需保留动态PE 作参考列，改名 `EP_DYN` 且不计入合成。
- **验收**：抽样 3 只季节性强公司（白酒/旅游/农业），EP 与手算 TTM 一致；registry 备注列更新。

### 子项 2：NaN EPS 被当作亏损股罚 −3

- **证据**：`code/multi_factor_value.py` L296：`neg = (df['EPS_TTM'] <= 0) | (pd.to_numeric(df['EPS_TTM'], errors='coerce').isna())`——**缺失值与真实亏损混为一谈**，L298-299 对 ROE_TTM/CFO_NI_TTM 赋 −3.0 最低分
- **为什么是错**：数据不完整的小盘/次新股被系统性按"亏损股"惩罚——又一条幸存者/数据偏差通道；且与 L300 的 GPM 处理不一致（GPM 只对 `EPS_TTM <= 0` 罚 −3，NaN 不罚）——同一逻辑两种口径。
- **修改要求**：分离两个集合：`neg = EPS_TTM <= 0`（真实亏损 → −3）；`missing = EPS_TTM.isna()`（数据缺失 → 0 中性分，与现有 fillna(0) 一致）；GPM/ROE/CFO 三因子用同一套判定。docstring 写明。
- **验收**：合成用例——NaN EPS 股得分中性（0），−0.1 EPS 股得分 −3。

### 子项 3：GPM 字段口径从未验证（待实测）

- **证据**：L237 `'GPM': pd.to_numeric(r['销售毛利率'], errors='coerce')` 取**最新报告期**的销售毛利率；该字段在东财 yjbb 中是单季、累计还是 TTM 口径，项目**从未实测验证**过。
- **为什么是错**：若为累计口径（大概率），Q1 报告与 Q3 报告的毛利率不可比（季节性公司差异巨大）；若为单季，则是好事但需记录。**这是待验证风险，不是已证实错误——先实测再动代码。**
- **修改要求**：写 `_verify_gpm_caliber.py`：拉同一公司连续多期 yjbb，对比"销售毛利率"与手算（毛利TTM/营收TTM、当期累计、单季）的三种口径，确定字段口径；结论写入口径审计表（见 M6）。若为累计口径 → GPM 改为 `(毛利TTM)/(营收TTM)`（需利润表数据源）或明确降权/弃用。
- **验收**：口径实测报告归档 factor_docs/，结论落地。

### 子项 4：60日涨跌幅复权口径未验证未声明

- **证据**：L275 `df['MOM_60D'] = pd.to_numeric(df.get('60日涨跌幅'), errors='coerce')`；该字段来自东财 spot 快照，其复权口径（qfq/raw）从未验证、从未写入任何文档。
- **为什么是错**：收益类因子 qfq/hfq rank 不变（项目已实测 Spearman=1.0），动量因子大概率安全；但**未验证 = 不能声明**。且一旦某期 spot 接口改口径，因子静默漂移。
- **修改要求**：实测确认字段口径（对照 hfq 60 日收益手算）；结论写入口径审计表（M6）；代码注释声明口径。
- **验收**：口径审计表登记该项。

### 子项 5：VOL_RATIO（量比）是盘中快照指标，不可复现

- **证据**：L278 `df['VOL_RATIO'] = pd.to_numeric(df.get('量比'), errors='coerce')`。东财 spot 的量比 = 抓取时刻的实时量比，取值随抓取时间（早盘/午盘/收盘）变化。
- **为什么是错**：同一策略不同时刻运行产出不同分数——月度调仓因子用不可复现的实时指标，违反 SOP"结果可复现"原则；且快照时间不可控（无记录）。
- **修改要求**：改为可复现指标——如"过去 N 日日均换手率/前 M 日日均换手率"（自算，可复现），或直接弃用 VOL_RATIO（0.05 权重并入 TURNOVER 或价值组，需用户拍板+记 weight-change）。若保留，至少记录抓取时间并弃用早盘快照。
- **验收**：同一天不同时刻跑两次，VOL_RATIO 分布一致（若弃用则无此字段）。

### 子项 6：相关性闸门失效（SOP 0.7 砍 vs 代码 0.5 只警告）

- **证据**：`docs/SOP.md` §3.2-5："|corr|>0.7 的因子对砍 IC 弱者或权重减半"；代码 L316-328：`if abs(v) > 0.5: flagged.append(...)` **只打印 ⚠️ 警告，不做任何处理**；且 corr 在**未 winsorize 的原始值**上计算（L316 `df[factor_cols].corr()`，含极端值、NaN 成对删除）。
- **为什么是错**：SOP 的硬闸门在代码里是软提示；阈值不一致（0.7 vs 0.5）；相关性在污染数据上估计，矩阵不可信。
- **修改要求**：① 阈值与 SOP 对齐（0.7）；② corr 改在 **winsorize 后的 z 值**上计算；③ 触发闸门时实际执行处理：砍 IC 弱者或权重减半（处理动作写代码+日志，处理结果记 weight-change）；④ 若当前组合有 |corr|>0.7 的因子对（EP×BP 高度疑似），按闸门处理后重跑选股验证。
- **验收**：合成高相关因子对（corr≈0.85），闸门实际改变权重；处理动作有日志记录。
