## 1. 问题现状

同一个事实（因子定义、成本模型、复权口径、权重）同时存在于 SOP、factor_docs、Wiki 三处，没有单一事实源机制，已经在漂移（SOP §2 结构树过时就是实例）。操作日志出现自相矛盾条目。confidence 体系无证据支撑。

## 2. 证据

1. **三轨重复**：成本模型在 `SOP.md §7 附录A` + `backtest_engineering_spec_v2.1.md` + `wiki/concepts/risk-management/backtest-cost-model.md` 三处并存；因子权重在代码 WEIGHTS + `factor-direction-map.md` + 各因子页 + registry 四处并存——任何一处改动，其余三处无人负责同步
2. **log.md 自相矛盾条目**（2026-08-21 迁移条目）："批量修正 wiki 11 个页面 + docs/SOP.md 的路径引用（G:/quant-investing/code → G:/quant-investing/code 或 /docs）"——**同一路径映射到自己**；备注"G:/quant-investing/code 已不再是正式目录"——同一句话里该路径既是又不是正式目录
   > ↑ 此处**引号内为 log.md 原文**，按「引用不改」保留旧路径 `G:/quant-investing`（对应条目见 `wiki/log.md` L61，原文同样保留）。2026-10-09 全库迁移时，本文件正文的自身引用已改为新路径，但**引文按原文保留**——避免出现「引文与被引文件不一致」。
3. **confidence 形同虚设**：10 个因子页标 medium/high，但零检验证据（S1）——按 SCHEMA 定义"high = 多个独立来源交叉验证，近期回测/实盘支持"，没有任何页面满足

## 3. 为什么是错

没有单一事实源 = 必然漂移；漂移的知识库 + 自相矛盾的日志 = 复盘时无法判断哪个版本可信。项目花大力气建知识库，却让同一个数字存在三个可能不同的答案。

## 4. 修改要求

1. **定分工（写进 SOP §2）**：
   - SOP = 流程与规则唯一事实源（参数默认值只在此定义）
   - factor_docs = 工作文档（设计稿/审查报告/检验报告）
   - Wiki = 知识提炼层：**只引用** SOP/规范条款编号与检验报告编号，**不复制参数值**（页面写"见 SOP §7A"而非重抄佣金表）；必须复制时标注"同步自 X，更新于 Y"
2. **log.md 迁移条目勘误**：保留原记录（审计不可篡改），在其下加一行"勘误 2026-08-22：上条'路径引用'表述为复制错误，正确内容应为 C盘路径 → G盘路径全量替换；'已不再是正式目录'指 C 盘旧目录。原文保留以示审计。"
3. **confidence 重标**：10 个因子页 + 相关实体页按实际证据重标——无检验证据的一律 low（或加"先验待验"标签）；有检验报告的挂报告编号后升 medium；S1 任务完成后按检验结果再调
4. **同步检查点**：SOP 增加"文档同步清单"（每次改动代码/参数，列出必须同步的文档位置）；Wiki SCHEMA 更新策略一节增加"事实冲突时以 SOP/定稿规范为准，Wiki 页标注来源版本号"
