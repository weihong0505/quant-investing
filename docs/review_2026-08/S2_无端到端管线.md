## 1. 问题现状

文档描述的架构是"数据获取 → 因子计算 → 加权合成 → 卖出信号 → 回测引擎"，但**数据层不存在**，管线从未端到端跑通过一次。回测引擎 backtest.py 是死代码——金样本能喂它合成数据，但没有模块给它喂真实数据。

## 2. 证据

- `code/backtest.py` L12：docstring 明写"数据由 data_fetcher.py 提供"——**code/ 目录下没有 data_fetcher.py**
- `docs/SOP.md` L102-105：结构树里 data_fetcher.py / factors.py / backtest.py / report.py 全部标"(规划)"
- `code/data_cache/`、`code/output/`、`code/logs/` 三个目录**不存在**（G 盘实测）。`multi_factor_value.py` 在 import 时就会 `os.makedirs(CACHE_DIR)`（L46-47），目录不存在 ⇒ **主流程从未在 G 盘被 import 过** ⇒ 从未产出过选股表、回测报告、运行日志
- 唯一联网可跑的只有 multi_factor_value.py 选股，且其入口 run.py 必崩（见 C1）

## 3. 为什么是错

1. 引擎的 25/25 金样本验证全部是合成数据——引擎算术正确，但没有数据源 = 没有真实回测 = 策略有效性为零证据（联动 M4）
2. "系统"实际 = 6 个互不连接的模块 + 1 个崩溃的入口。项目所有关于"系统/管线"的表述（Wiki multi-factor-v2 页架构图、SOP 输出规范）是纸面的
3. 没有数据层，S1（因子检验）、M5（符号验证）、M2（组合检验）全部无法执行——这是整个项目的卡脖子环节

## 4. 修改要求

1. 新建 `code/data_fetcher.py` 统一数据层，职责：
   - 缓存（parquet，`data_cache/{接口}_{参数}_{日期}.parquet`，先查缓存后拉取）
   - 重试 3 次指数退避（2s/4s/6s）+ 请求间隔 ≥0.5s
   - **多源降级矩阵**：东财 → 新浪 `stock_zh_a_daily`（个股复权严格正确）→ 腾讯 `stock_zh_a_hist_tx`（退市股/ETF hfq 可得）；跨源只校验不拼接
   - 提供引擎所需标准输入：交易日历、raw 开盘/收盘价、hfq 收盘价、总市值、tradable（停牌）、ST 标记、现金分红 cash_div、送转 share_ratio
   - 退市股纳入历史池（名单 `stock_info_sh_delist`/`stock_info_sz_delist`，行情用腾讯源），按终止上市日期动态剔除——防幸存者偏差
2. 打通端到端管线：数据（data_fetcher）→ 选股（multi_factor_value）→ 信号（sell_signals）→ 引擎（backtest）→ 报告（净值+交易+绩效+基准对比）
3. 数据落库优先级：510300/510500 ETF hfq（基准）→ 全 A 历史行情 → yjbb/zcfz 财务逐期 → 指数价格序列（辅基准）
4. 输出规范按 SOP §3.4：`output/pick_{YYYYMMDD}.csv`（utf-8-sig）、`output/backtest_{策略名}_{YYYYMMDD}.html`、`logs/run_{时间戳}.log`
