## 1. 设计文档全文要点摘要

来源：`docs/research/regime_based_weights.md`（2026-08-21，全文 3.1KB，以下为完整要点）。

### 1.1 动机
- 主策略 v2 使用**固定权重**（价值 40% + 质量 25% + 动量 15% + 流动性 10% + 规模 5% + 情绪 5%）。
- 固定权重的问题：① 2019–2021 成长碾压期价值因子系统性弱势（风格现象），固定权重硬扛长期跑输；② 2021 后价值回归，固定权重又充分受益；③ 因子短期 IC 波动大（**月度 IC 标准差 ~0.10~0.13**），固定权重无法利用短期信号强度。

### 1.2 设计红线（设计文档 §2）
1. **不得违反防过拟合纪律**：权重调整规则必须在样本外确定，一次确认制
2. **调整幅度有上限**：单因子权重偏离基准权重 ≤ ±50%（防权重漂移失控）
3. **低频调整**：季度调权（月度调权换手成本会吃掉收益）
4. **任何调整必须可解释**：规则简单透明，禁止黑箱 ML 调权
5. 实施前走 **MImo 审批 + v3 检验**

### 1.3 Regime 识别方案（候选，需 MImo 裁决）

| 方案 | 信号 | 优点 | 缺点 |
|------|------|------|------|
| A. 滚动 IC 调权 | 各因子过去 **36m ICIR** | 直接反映因子近期有效性；与 v3 滚动 36m 观察线一致 | **ICIR 噪声大（36m 窗口功效有限）**（设计文档自认） |
| B. 市场状态调权 | 市场动量（过去 12m 指数收益正负）+ 波动率分位 | 状态驱动，与经济直觉吻合 | 状态与因子表现的映射需要验证 |
| C. 制度段固定权重组 | 按 A股制度段（2019前/注册制过渡/全面注册制）预设权重 | 最简单透明 | 段内不调整，错过段内轮动 |
| D. A+B 混合 | 状态粗分 + 滚动 IC 微调 | 兼顾 | 复杂，参数更多，过拟合风险 |

**倾向：先做 A**，理由：① 与 v3 的滚动 36m ICIR 观察线**复用同一统计量**，无新增过拟合面；② 天然满足"因子 IC 月度跟踪"（P1 已建 ic_monitor.py）的数据流；③ 权重调整 = 归一化的 max(ICIR, 0) 或 ICIR 加权。

### 1.4 拟议公式（设计文档 §4，供 MImo 审查）

```
季度调权:
  w_i^base = 基准权重（当前固定权重）
  icir_i   = 因子 i 过去 36m ICIR
  raw_i    = max(icir_i, 0.1)          # 地板防归零
  w_i      = w_i^base × raw_i / mean(raw)   # 按 ICIR 相对强弱缩放
  约束: 0.5 × w_i^base ≤ w_i ≤ 1.5 × w_i^base   # 幅度上限
  归一化: w_i = w_i / Σw
```

### 1.5 验证要求（设计文档 §5，实施时）
1. **Walk-forward**：每季度用"截至调权日过去 36m"的 ICIR 调权（**严格 PIT，无未来函数**）
2. 对比固定权重：净收益（扣成本）、换手增量、**2x 成本敏感性**
3. **调权增益必须 > 换手成本增量**（季度调权换手通常 <5%/次，成本可控）
4. MImo 审批 + **参数敏感性（地板 0.1、幅度上限 50%、窗口 36m 各 ±20% 扰动）**

### 1.6 待办依赖（设计文档 §6）
- 需先有**全市场历史 IC 数据**（依赖东财解封 → data_fetcher 落地）
- P1 的 `ic_monitor.py` 已就绪，数据流接口：`ic_series(factor_table, return_table)`、`rolling_icir(ic, window=36)`（实测签名见 §2.4）

### 2.1 `regime_weights()` 单点调权函数 —— 已实现，冒烟测试通过

## 4. 待审问题清单（5 项；问题 1–4 为 C8 指定重点，问题 5 为送审人补充）

### 问题 1（核心）：36m 窗口 ICIR 估计误差下，季度调权的增量价值是否成立？
**证据链**：
- a. v3 §8 中滚动 36m ICIR 仅是**报告项/观察线**，定位是监控预警（观察线判据甚至要求"连续 ≥12 月为负"这种长持续性标准），**从未被设计为实盘调权输入**。方案 A 把它从"监控统计量"提升为"组合权重决策输入"，用途等级跨越没有方法论背书。
- b. 项目实测（backtest_engineering_spec 审查结论）：**90 月回测对 3% 超额（TE10%）检出功效仅 20.3%**——比 36m 窗口更长仍功效不足，36m ICIR 与 0 的区分能力更弱。
- c. 量级对照：设计文档自述月度 IC 标准差 ~0.10~0.13 → 36m 均值 IC 的标准误 ≈ 0.017~0.022，与 v3 §4.3 的 |mean IC| ≥ 0.02 通过线**同量级**；v3 §1 又规定样本 <60 月结论只能算"初步"——36m 连 v3 自己的最低样本线（60m）都不到。
- d. 用噪声 ICIR 调权 = 把估计噪声直接注入权重，**可能放大而非缩小组合风险**；且"调权增益必须 > 换手成本增量"（设计文档 §5-3）在噪声信号下是否可证，无任何实测。
**请 MImo 裁决**：36m 窗口下季度调权的期望增量价值（净收益 vs 固定权重）是否成立？若不成立：① 是否应改用更长窗口（如 60m，对齐 v3 最低样本线）？② 是否应降级为"观察/实验性"，仅报告不实盘？③ 还是方案 A 整体让位于 B/C/D？

### 问题 2：高相关因子被同步加成的处理（是否需相关性惩罚）？
**证据链**：
- a. 调权公式对每个因子**独立**缩放，无相关性项——同一风格因子对（如 EP 0.2 与 BP 0.2，价值对；TURNOVER 0.1 与 VOL_RATIO 0.05，流动性/波动对，v3 §4.4-6 点名这两类可能互为波动率代理）在风格行情中 ICIR 往往**同向走强**，会被同步加成 = 对同一风险暴露加倍下注。
- b. 现有共线性闸门只覆盖**集成阶段**：SOP §3.2-5（|corr|>0.7 砍 ICIR 弱者或权重减半）与 v3 §7-1（取 ICIR 较强者，训练段裁决）均针对"新因子进存量组合"，**对动态调权阶段的权重相关性无任何约束**；v3 §7-4 的 VIF>5 告警同样只约束合成前静态检查。
- c. 集中度风险：ICIR 走强在风格行情中系统性同向（2019–2021 成长碾压期价值类 ICIR 集体走弱 → 方案 A 会把价值权重集体压到下限、成长/动量类集体抬到上限），调权会**系统性推高风格暴露**，与设计红线 2"防权重漂移失控"的精神可能相悖。
**请 MImo 裁决**：动态调权是否需要相关性惩罚/聚类后调权（如先对 |corr|>0.7 因子对合并 ICIR 或权重减半）？还是可接受（论据：基准权重已含共线性处理）？若接受，请说明为什么集成阶段要管相关性、调权阶段可以豁免。

### 问题 3：floor=0.1 / ±50% / 36m 参数的敏感性
**证据链**：
- a. 三个参数**均无任何实测依据**，设计文档 §5-4 自己要求"各 ±20% 扰动"的敏感性测试，但当前取值（0.1 / 0.5 / 36m）是拍板值。
- b. **floor=0.1 语义问题**：`raw = max(icir, 0.1)`——负 ICIR 因子（如 ICIR=−1）的 raw 被抬到 0.1，参与相对缩放后其权重仍可保留相当比例（且受 ±50% 下限保护）。"防归零"与"调权应反映有效性"存在张力：**强负 ICIR 因子是否应被更积极压制，而非地板抬升？** 另需注意地板与 ±50% 下限的耦合：当全体 raw 压缩在 0.1~0.3 区间时地板主导；当 ICIR 分化大时 ±50% 下限主导——实际约束力随市场状态切换。
- c. ±50% 上限与归一化迭代 50 次耦合，实际可达权重区间需模拟验证（当前只有合成数据冒烟，无真实分布验证）。
- d. **"无新增过拟合面"的说法存疑**：设计文档 1.3 倾向 A 的理由是"复用同一统计量，无新增过拟合面"——但 floor、max_dev、window、调权频率 4 个参数本身就是新的拟合面；且红线 1 要求"规则在样本外确定，一次确认制"，参数取值是否属于"样本外确定"缺乏证据。
- e. 调权频率（季度）与 v3 §6 冲突：v3 §6 要求"月度 vs 季度再平衡**净收益实证对比**，哪个高用哪个"，设计文档直接断言季度（"月度调权换手成本会吃掉收益"），**未做实证**。
**请 MImo 裁决**：三参数取值是否放行？负 ICIR 因子的地板语义是否需改为"截断到 0 或负值参与"？±20% 敏感性测试是否应列为实施前置条件（见 §5-4）？调权频率是否需要先补 v3 §6 式实证？

### 问题 4：与"先检验后集成"纪律的关系（因子未过检验前调权是否违规）？
**证据链**：
- a. SOP §3.0.1/3.0.2：统计检验是因子进入 WEIGHTS 的前置条件；未检验因子权重必须标注"实验性"，不得作为实盘依据；"未过审的因子不得进入主策略"。
- b. **项目现状（复盘 S1，🔴 最致命）**：10 个在册因子**零统计检验**——registry 的 IC均值/ICIR/NW-t/PT MR p/净多空/夏普/2x成本列全部"—"，`factor_docs/` 内无任何 `test_{因子}_{日期}.md`。当前主策略的**固定权重本身就没有检验依据**。
- c. 推论：若固定权重无检验依据，动态调权在"谁该被调高"上同样无依据；调权不解决检验缺失，反而在未检验的权重上**叠加第二层自由度**（权重规则又多一组参数）。
- d. v3 §12 流程顺序：检验 → 滚动 ICIR 稳健性 → MImo 审批 → 入主策略；方案 A 属于"因子逻辑重大修改"，按 SOP §3.0 属审批范围，且统计上依赖检验结论。

### 问题 5（送审人补充）：`regime_weight_history()` 接口设计与 PIT 边界
**证据链**：
- a. 现状签名 `(base_weights, factor_table, return_table, quarterly_dates, ic_window=36)`，docstring 声明 factor_table "index=月末, columns=代码, values=因子值"，但函数体注释承认"因子是外部分组"、L98 又说"因子值表需按因子分组传入"——**接口语义自相矛盾**，这正是 NotImplementedError 无法落地的原因之一。
- b. 复盘 C8 修改要求指明方向：输入改为明确的 `factors_ic: Dict[str, pd.Series]`（每因子一条全历史 IC 序列，由 `ic_monitor.ic_series` 产出），对每个季度调权日取该日之前 36m 窗口算 ICIR → 调权 → 输出权重历史 DataFrame。
- c. PIT 严格性：设计文档 §5-1 要求"严格 PIT，无未来函数"——调权日只能用其之前的数据；是否需要数据版本 hash / 对齐约束来机械保证（防未来函数），v3 §12 要求"数据版本 hash + 脚本路径"登记。
